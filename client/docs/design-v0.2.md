## 一、产品一句话

> 学生 A 发单求助取快递 → 学生 B 帮忙跑腿 → 钱结清

**就是这么简单。**

---

## 二、3 个菜单（TabBar）

| # | 菜单名 | 干嘛的 |
|---|---|---|
| 1 | **发任务** | 填写快递信息、地址、跑腿费，一键发布 |
| 2 | **我的单** | 我发布过的所有订单，看状态、点详情、签收、取消 |
| 3 | **我的** | 头像、昵称、学校、退出 |

**没有跑腿大厅？** —— 见下方「待确认」第 1 点。

## 三、核心业务流程

```
          发任务                          我的单                         我的
     ┌──────────┐                   ┌──────────┐                  ┌──────────┐
     │ 填驿站    │                   │ 看订单状态│                  │ 基础资料  │
     │ 填地址    │ ──发布──▶ 进入大厅 │ 点详情    │ ──操作──▶       │ 退出登录  │
     │ 填跑腿费  │                   │ 取消/签收 │                  │          │
     └──────────┘                   └──────────┘                  └──────────┘
```

## 五、订单状态机（极简版，4 个状态）

```
待接单 ── 被人接单 ──▶ 进行中 ── 送达 ──▶ 已完成
  │                                         
  └── 发单者取消 ──────────────────────────▶ 已取消
```

### 状态 × 操作

| 当前状态 | 发单者能做 |
|---|---|
| 待接单 | 取消订单 / （等别人来接） |
| 进行中 | 联系跑腿者 |
| 已完成 | ——（结束） |
| 已取消 | ——（结束） |

## 八、待确认（最后几个问题）

**必须回答才能进入 UI 设计**：

### 1. "谁来接单？"（最关键）

砍了跑腿大厅之后，订单发布出来**谁接？** 有 3 种理解：

| 方案 | 说明 | 推荐 |
|---|---|---|
| **A. 朋友帮忙** | 发单用微信把订单**分享给朋友/群聊**，朋友点链接接单，朋友也需要用这个小程序 | ⭐⭐⭐ 真实场景，校园里就是熟人互助 |
| **B. 所有人双身份** | 我的小程序里"发任务"菜单只是一个 Tab，其实用户也可以在别的地方看到待接单并抢 | ⭐⭐ 需要恢复跑腿大厅或接单入口 |
| **C. 纯展示** | MVP 阶段**没有真接单**，所有状态都是自动流转的（比如点"发布"就自动变成"已接单"），纯展示 UI 效果 | ⭐ 最快，但没走通闭环 |

**你选哪个？**

### 2. "我的单" 显示什么？

- A. **只显示我发的**（最简单）
- B. 上面一个 Tab 切换：**我发的 / 我帮别人跑的**

### 3. 其他有没有要加的？

- 评价系统（给跑腿者打分）
- 钱包（充值/提现）
- 加急小费
