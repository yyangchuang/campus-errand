## 一、项目概述

### 1.1 项目背景
大学校园内，快递驿站普遍离宿舍较远（500m~2km），学生经常遇到：
- 下雨/没课懒得出门取快递
- 大件行李箱搬不动
- 多件快递要跑好几个驿站
- 急件（文件/生鲜）必须马上取但走不开

### 1.2 产品定位
**微信小程序**，连接发单学生和跑腿员，让"帮忙取快递"变成一个可交易、可追踪、可评分的服务。

### 1.3 核心价值
| 对发单用户 | 对跑腿员 |
|-----------|---------|
| 不用出门，躺着收快递 | 赚零花钱（利用碎片时间） |
| 大件/多件省心 | 认识更多同学 |
| 价格透明（小¥3/中¥5/大¥10/急¥15） | 评分积累信誉，未来接高价单 |

### 1.4 MVP 范围（本次实现）
✅ 登录（手机号自动识别角色，mock）
✅ 发单（选驿站 + 填快递 + 填地址 → 立即支付）
✅ 抢单（跑腿员浏览待接单列表）
✅ 状态流转（5 步：已发布 → 已接单 → 运送中 → 已送达 → 已完成）
✅ 送达凭证（跑腿员送达时拍照）
✅ 订单详情（进度追踪 + 送达凭证 + 底部操作按钮）
✅ 我的单（发单用户只看自己发的，跑腿员只看自己接的）
✅ 我的（个人信息 + 统计 + 跑腿员收入周/月/累计）
✅ 交易（发单即付款，取消自动退款，MVP 模拟）
❌ 评价系统
❌ 消息推送
❌ 真实微信支付

## 二、角色与权限

### 2.1 三种角色

| 角色 | 说明 | 谁能当 | MVP 识别方式 |
|------|------|--------|-------------|
| **发单用户（user）** | 发布快递需求、付款、签收 | 所有在校学生 | 手机号不以 1350000/1340000 开头 |
| **跑腿员（runner）** | 抢单、取件运送、送达凭证 | 管理员手动添加 | 手机号以 `1350000` 开头 |
| **管理员（admin）** | 派单、管理用户 | 暂不实现独立后台 | 手机号以 `1340000` 开头 |

| 取消已付款订单（自动退款） | ✅（pending/accepted） | — | — |
| 抢单 | — | ✅ | — |
| 取件→运送 | — | ✅（仅自己接的单） | — |

## 四、订单状态机

### 4.1 状态定义

| 状态 | 值 | 说明 | 谁触发 |
|------|----|------|--------|
| 已发布 | `pending` | 订单创建 + 已付款，等待跑腿员 | 发单用户（付款后） |
| 已接单 | `accepted` | 跑腿员接了单 | 跑腿员 |
| 运送中 | `delivering` | 跑腿员已取件 | 跑腿员 |
| 已送达 | `delivered` | 跑腿员送到了（可拍照凭证） | 跑腿员 |
| 已完成 | `completed` | 发单用户确认签收 | 发单用户 |
| 已取消 | `cancelled` | 发单用户取消，已付款自动退款 | 发单用户 |

### 4.2 状态流转图

```
发单用户（付款）     跑腿员           跑腿员           跑腿员         发单用户
     │                 │                │                │              │
     ▼                 ▼                ▼                ▼              ▼
 ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
 │ pending  │───►│ accepted │───►│delivering│───►│ delivered│───►│completed│
 │ 已发布    │    │ 已接单   │    │ 运送中    │    │ 已送达    │    │ 已完成   │
 │(已付款)  │    │          │    │          │    │(可拍凭证)│    │          │
 └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
      │               │
      │ 发单用户取消（自动退款）
      └─────────► ┌──────────────┐
                 │  cancelled    │
                 │ 已取消·已退款 │
                 └──────────────┘
```

### 4.3 交易流程

```
发单用户点击"立即发布"
  → 弹窗"确认支付 ¥X"
  → 确认 → 创建订单 (paid: true, payMethod: 'mock')
  → 状态: pending

发单用户取消已付款订单（pending/accepted）
  → 弹窗"确认取消并退款 ¥X"
  → 确认 → 状态: cancelled, refunded: true, refundAt: now
  → 进度条显示"已取消·已退款"

跑腿员送达
  → 弹窗"拍照凭证 / 直接送达"
  → 拍照: 调 wx.chooseMedia → 存本地临时路径
  → 状态: delivered, 附带 deliveryProof / deliveredAt
```

### 4.4 旧状态迁移（兼容）

| 旧状态 | 迁移到 |
|--------|--------|
| `picking` | `accepted` |
| `paid` | `delivered` |

## 五、定价规则

### 5.1 统一定价（平台规定）

| 包裹类型 | key | 价格 | 说明 |
|---------|-----|------|------|
| 小包裹 | `small` | ¥3 | 衣服/零食/手机壳/耳机 |
| 中包裹 | `mid` | ¥5 | 鞋盒/书/日用品/文件 |
| 大包裹 | `big` | ¥10 | 行李箱/大箱子/天猫超市 |
| 急件/特殊 | `urgent` | ¥15+ | 易碎/生鲜/急件/大件搬运 |

### 5.2 总价计算

```
订单总价 = Σ (每个包裹的 price)
```

### 5.3 定价时机
- 选包裹类型 → 自动填入价格
- 添加快递时胶囊标签显示 "¥3"/"¥5" 等
- 总价卡片实时计算

## 八、核心流程

### 8.1 发单 + 支付流程

```
登录 → 选驿站 → 加快递 → 填地址 → 点"立即发布"
  │
  ▼
弹窗"确认支付 ¥X"
  │
  ├─ 取消 → 返回编辑
  └─ 确认
     │
     ▼
创建订单 (paid: true, payMethod: 'mock', status: 'pending')
  │
  ▼
跳"我的单"→ 发单用户看到这个 pending 订单
```

### 8.2 跑腿员接单送达流程

```
跑腿员登录 → "待接单"页 → 点"立即抢单" → accepted
  │
  ▼
进详情页 → 点"已取件，开始运送" → delivering
  │
  ▼
点"已送达"
  │
  ├─ "拍照凭证" → wx.chooseMedia → 存图片路径 → delivered
  └─ "直接送达" → delivered (无凭证)
  │
  ▼
发单用户看到"已送达"状态 + 送达凭证图片
```

### 8.3 取消 + 退款流程

```
发单用户在 pending/accepted 状态
  │
  ▼
点"取消订单"
  │
  ├─ 已付款 → 弹窗"确认取消并退款 ¥X" → cancelled + refunded: true
  └─ 未付款 → 弹窗"取消订单" → cancelled
  │
  ▼
进度条顶部显示"已取消·已退款"（灰化）
```

### 8.4 收入统计计算

```
跑腿员"我的"页 calcIncome()
  │
  ▼
过滤 runnerId === 当前用户 openid + status === 'completed' 的订单
  │
  ├─ 用 timeline 里 completed 事件的时间过滤
  ├─ 本周: 周一 00:00 起
  ├─ 本月: 每月 1 号 00:00 起
  └─ 累计: 无时间过滤
  │
  ▼
三个 Tab 切换显示 count + total
```
