## 一、产品一句话

> 同学 A 发单 → 平台认证的跑腿员 B 接单 → 送达 → 签收

---

## 二、两类角色 + 权限层级

| 角色 | 谁能当 | 能干什么 |
|---|---|---|
| **普通用户（发单者）** | 所有同学，微信授权即可 | 发任务 + 看自己的单 |
| **跑腿员（接单者）** | 管理员手动添加白名单 | 接任务 + 看自己接的单 |
| **管理员** | 运营负责人 | 管理跑腿员名单 + 派单 |

**核心规则**：
- 一个账号只能是其中一种角色，不双身份
- 普通用户没有任何接单入口，看不到待接单池
- 跑腿员由管理员**手动添加**（数据库改 role 字段为 runner）
- 管理员可随时移除/停用某跑腿员

## 四、接单模式（双模式并存）

### 模式一：抢单

```
发单者发布订单
       │
       ▼
  进入"待接单池"   ← 所有跑腿员可见
       │
       ▼
跑腿员谁先点"立即接单" → 归谁
       │
       ▼
订单状态 → 跑腿中，其他人不可见
```

**适用**：通用订单，酬金高的先被抢

### 模式二：派单

```
管理员在后台选订单 → 选某个跑腿员
       │
       ▼
订单直接进入"该跑腿员的专属列表"
       │
       ▼
跑腿员打开"待接单" → 看到"派单"标记
       │
       ▼
跑腿员点"接受派单" / "拒绝"
       │
       ├─ 接受 → 订单归他
       └─ 拒绝 → 回到派单池，管理员重新派
```

**适用**：急单、大单、或指定某跑腿员负责

### 数据模型（订单表加两个字段）

```sql
orders {
  id
  ...
  take_mode       // 'grab' 抢单 | 'assign' 派单
  assign_to       // 派单时存跑腿员 user_id（抢单时为空）
  taker_id        // 最终接单者 user_id（接单后填入）
}
```

### 跑腿员"待接单"页长这样

```
┌─────────────────────────────┐
│ 🔔 派单给我 (2)              │  ← 顶部醒目标签
│  ┌─────────────────────────┐│
│  │ 📦 菜鸟驿站，3件大件     ││
│  │ 派单 · 酬金 ¥15          ││
│  │        [接受] [拒绝]     ││
│  └─────────────────────────┘│
│                             │
│ 🔥 可抢单 (8)               │  ← 下面抢单池
│  ┌─────────────────────────┐│
│  │ 📦 顺丰急件              ││
│  │ 抢单 · 酬金 ¥12 · 3分钟前││
│  └─────────────────────────┘│
│  ┌─────────────────────────┐│
│  │ 📦 京东大件              ││
│  │ 抢单 · 酬金 ¥10 · 8分钟前││
│  └─────────────────────────┘│
└─────────────────────────────┘
```

## 五、登录方案

### MVP 阶段（前端实现）

```javascript
// 登录页就一个按钮
<button bindtap="onLogin">微信一键登录</button>

onLogin() {
  wx.login({
    success: (res) => {
      // res.code 发给后端换 openid
      // MVP 阶段可以 mock 一个固定 openid 本地判断 role
    }
  });
}
```

- **openid**：微信给的唯一标识，MVP 够用
- **不拿手机号**：先跳过，不影响闭环
- **默认 role**：新注册用户默认 `user`，管理员手动改成 `runner`

### 后期（接后端时升级）

```xml
<button open-type="getPhoneNumber" bindgetphonenumber="onGetPhone">
  微信手机号一键登录
</button>
```

- 后端用 code 换真实手机号
- 用户体验更好，运营方便

## 十、技术实现要点

### 数据表（后端）

```sql
users {
  id, openid, nickname, avatar, school,
  role: 'user' | 'runner' | 'admin',
  runner_no, created_at
}

orders {
  id, publisher_id, publisher_name,
  express_station, station_location,
  deliver_to, deliver_note,
  package_count, package_desc,
  reward, tip,
  status,                          // pending/running/delivered/completed/cancelled
  take_mode,                       // grab / assign
  assign_to,                       // 派单时的跑腿员 id
  taker_id, taker_name,            // 实际接单者
  created_at, completed_at
}
```

### TabBar 动态渲染（微信小程序实现方式）

**关键**：微信小程序 TabBar 配置在 `app.json` 里是固定的，**不能动态改**。

**解决方案**：**自定义 TabBar**。

```javascript
// app.json 里加一行
{
  "tabBar": { "custom": true, ... }
}

// 然后自己写一个 custom-tab-bar 组件
// 根据 globalData.role 渲染不同的菜单
```

### 登录判断流程

```
小程序启动
    │
    ▼
wx.login() 拿 code
    │
    ▼
发给后端换 openid
    │
    ▼
查 users 表
    │
    ├─ 有记录 → 返回 { role, ... } → 渲染对应 TabBar → 进首页
    │
    └─ 无记录 → 新建用户 role=user → 返回 → 进首页（发单者版）
```
