## 一、项目概述

### 1.1 项目背景
大学校园内，快递驿站普遍离宿舍较远（500m~2km），学生经常遇到：
- 下雨/没课懒得出门取快递
- 大件行李箱搬不动
- 多件快递要跑好几个驿站
- 急件（文件/生鲜）必须马上取但走不开

### 1.2 产品定位
**微信小程序**，连接发单学生和跑腿员，让"帮忙取快递"变成一个可交易、可追踪、可评分的服务。

### 1.3 核心价值
| 对发单用户 | 对跑腿员 |
|-----------|---------|
| 不用出门，躺着收快递 | 赚零花钱（利用碎片时间） |
| 大件/多件省心 | 认识更多同学 |
| 价格透明（小¥3/中¥5/大¥10/急¥15） | 评分积累信誉，未来接高价单 |

### 1.4 MVP 范围（本次实现）
✅ 登录（一键切换角色，mock）
✅ 发单（选驿站 + 填快递 + 填地址 → 发布）
✅ 抢单（跑腿员浏览待接单列表）
✅ 派单（管理员派给指定跑腿员）
✅ 状态流转（4 步：已发布 → 已接单 → 运送中 → 已完成）
✅ 订单详情（进度追踪 + 底部操作按钮）
✅ 我的单（发单用户双 Tab，跑腿员单 Tab）
✅ 我的（个人信息 + 统计 + 角色切换）
❌ 支付（MVP 阶段跳过，假设线下/信用）
❌ 评价系统
❌ 消息推送

## 二、角色与权限

### 2.1 三种角色

| 角色 | 说明 | 谁能当 |
|------|------|--------|
| **发单用户（user）** | 发布快递需求、查看订单、签收 | 所有在校学生 |
| **跑腿员（runner）** | 抢单/接派单、取件运送 | 管理员手动添加（MVP），后续开放申请审核 |
| **管理员（admin）** | 派单、管理用户 | 暂不实现独立后台 |

### 2.2 角色能力矩阵

| 功能 | 发单用户 | 跑腿员 | 管理员 |
|------|:--------:|:------:|:------:|
| 发布订单 | ✅ | — | ✅ |
| 取消自己发的订单 | ✅（pending/accepted 状态） | — | — |
| 抢单 | — | ✅ | — |
| 接收派单 | — | ✅ | — |
| 拒绝派单 | — | ✅ | — |
| 取件→运送 | — | ✅（仅自己接的单） | — |
| 确认签收 | ✅（仅自己发的单） | — | — |
| 查看取件码 | — | ✅（仅自己接的单） | — |
| 联系对方 | ✅ | ✅ | — |
| 派单 | — | — | ✅ |

## 四、订单状态机

### 4.1 状态定义

| 状态 | 值 | 说明 | 谁触发 |
|------|----|------|--------|
| 已发布 | `pending` | 订单刚创建，等待跑腿员 | 系统 |
| 已接单 | `accepted` | 跑腿员接了单，可能还没出发 | 跑腿员 |
| 运送中 | `delivering` | 跑腿员已取件，正在送往宿舍 | 跑腿员 |
| 已完成 | `completed` | 发单用户确认签收 | 发单用户 |
| 已取消 | `cancelled` | 发单用户取消 / 跑腿员拒绝派单 | 发单用户 / 跑腿员 |

### 4.2 状态流转图

```
                    发单用户取消 (runner未出发)
                    ┌─────────────────────────┐
                    │                         ▼
 ┌──────────┐ 接单  │  ┌──────────┐ 运送中  ┌──────────────┐ 签收  ┌──────────┐
 │ pending  │──────►└─►│ accepted │──────► │  delivering  │────► │ completed│
 │ 已发布   │           │ 已接单   │        │   运送中     │      │ 已完成   │
 └──────────┘           └──────────┘        └──────────────┘      └──────────┘
      │                                                       ▲
      │ 跑腿员拒绝派单                                          │
      └─────────────────────────────────────► 已取消(cancelled)
```

### 4.3 旧状态迁移（兼容）

MVP 之前的版本有 `picking` / `delivered` 状态，自动迁移：
- `picking` → `accepted`
- `delivered` → `delivering`

## 五、定价规则

### 5.1 统一定价（平台规定）

| 包裹类型 | key | 价格 | 说明 |
|---------|-----|------|------|
| 小包裹 | `small` | ¥3 | 衣服/零食/手机壳/耳机 |
| 中包裹 | `mid` | ¥5 | 鞋盒/书/日用品/文件 |
| 大包裹 | `big` | ¥10 | 行李箱/大箱子/天猫超市 |
| 急件/特殊 | `urgent` | ¥15+ | 易碎/生鲜/急件/大件搬运 |

### 5.2 总价计算

```
订单总价 = Σ (每个包裹的 price)
```
一个订单里可以有多个包裹，每个包裹独立定价，最后相加。

### 5.3 定价时机
- 发单时：选包裹类型 → 自动填入价格
- 添加快递时：胶囊标签上显示 "¥3"/"¥5" 等
- 总价卡片：实时计算，发单用户可见

## 六、数据模型

### 6.1 User（用户）

```javascript
{
  openid: string,       // 唯一标识（MVP 用 user_001 / runner_001）
  nickname: string,     // 昵称
  role: 'user' | 'runner' | 'admin',
  avatar: string,       // emoji 头像
  phone: string,        // 手机号（脱敏）
  school: string,       // 学校
  stats: {
    publishCount: number,   // 累计发单
    acceptCount: number,    // 累计接单（跑腿员）
    completeCount: number,  // 累计完成
    rating: number          // 评分（跑腿员）
  }
}
```

### 6.2 Order（订单）

```javascript
{
  id: string,              // 订单号 E + 时间戳 + 随机
  userId: string,          // 发单用户 openid
  runnerId: string | null, // 接单单员 openid
  runnerName: string,      // 跑腿员昵称（冗余，方便展示）

  takeMode: 'grab' | 'assign',  // 抢单 / 派单
  assignTo: string | null,      // 派单目标 openid

  stationId: string,       // 驿站 ID
  stationName: string,     // 驿站名称
  stationAddr: string,     // 驿站地址

  packages: [              // 包裹列表
    {
      express: string,     // 快递公司
      code: string,        // 取件码
      tail: string,        // 手机尾号
      ptype: string,       // small / mid / big / urgent
      price: number,       // 价格
      name: string         // 备注名（可选）
    }
  ],

  address: string,         // 送达地址
  note: string,            // 备注
  total: number,           // 总价
  status: string,          // pending / accepted / delivering / completed / cancelled

  createdAt: timestamp,   // 创建时间
  timeline: [              // 状态时间线
    { at: timestamp, status: string }
  ]
}
```

### 6.3 Station（驿站）

```javascript
{
  id: string,     // cainiao_e / sf / jd / zt ...
  name: string,   // 菜鸟驿站（东门店）
  addr: string    // 东门体育馆旁
}
```

## 八、核心流程

### 8.1 发单流程

```
发任务页
  │
  ├─ 选择驿站 ▼ picker
  │
  ├─ 点"+ 添加快递" ──► 半屏弹窗
  │                       │
  │                       ├─ 标签选快递公司
  │                       ├─ 填取件码
  │                       ├─ 填尾号（默认手机尾号）
  │                       ├─ 胶囊选包裹类型（自动定价）
  │                       ├─ 📷 扫码识别 / ✋ 手动修改 可互相切换
  │                       └─ 确认添加 ✓
  │
  ├─ 送达地址 input
  ├─ 备注（可选） textarea
  │
  ├─ 总价实时计算
  │
  └─ 点击"立即发布" ──► 校验 ──► 存入 orders ──► 跳"我的单"
```

### 8.2 抢单流程

```
跑腿员进入"待接单"
  │
  ├─ 浏览抢单列表（所有 pending + grab 模式）
  │
  ├─ 点击"立即抢单" ──► 校验订单还在 pending ──►
  │     ├─ runnerId = 当前用户 openid
  │     ├─ status = accepted
  │     └─ 自动跳转订单详情
  │
  └─ 或进入详情页 ──► 点"立即接单"
```

### 8.3 状态更新流程

```
跑腿员在详情页（accepted 状态）
  └─ 点"已取件，开始运送" ──► status = delivering

发单用户在详情页（delivering 状态）
  └─ 点"确认签收" ──► 弹窗确认 ──► status = completed

发单用户取消（pending / accepted 状态）
  └─ 点"取消订单" ──► 弹窗确认 ──► status = cancelled
```
